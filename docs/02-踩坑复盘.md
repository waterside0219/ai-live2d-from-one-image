# 踩坑复盘

这一篇记录我们实际走过的弯路。每个坑都按同样的顺序写：**现象 → 原因 → 修法 → 教训**。具体怎么做，请看[教程](01-教程.md)。

> 名词：**L1** 指拆图阶段。**r01、r02……** 是拆图阶段交付的版本号。**r1–r4d** 是建模之后、装进手机的版本号。**H 窗口** 是专门负责把模型接进手机的那一个 Astra 窗口。

## 坑1 原图被压成黑底 JPG

- **现象**：V1、V2 的边缘总有一圈黑灰色毛边，修不干净；黑色眼线和头顶的发圈被当成背景删掉了；细发丝只能做到约 1px 的收边。
- **原因**：阿年发的原图本来是透明 PNG，但按“照片”发送后，Telegram 把它压成了 960×1280 的黑底 JPG，透明背景被填成了黑色。我们从 10-21 到 10-29 一直在用这张压过的图。
- **修法**：10-29 22:20，阿年改用“文件”方式重新发送，我们才拿到真正的 RGBA 1086×1448 原图。之后的所有版本都用这一张。
- **教训**：收到图第一眼先查格式和 alpha。起点错了，后面做多少都是白做。

## 坑2 定稿立绘逐件 AI 重画，变了脸

| 版本 | 做法 | 结果 |
|---|---|---|
| r01 | 从原图提取，再补画被遮挡部分，共 54 层 | 自检没过：眼白层里混进了虹膜，脸底残留眼镜和发丝，镜框断断续续，几束头发出现断片，耳根补画不合格。根因是同一张完整的眼睛图被同时当成了眼白和虹膜的底图 |
| r02 | 同一路线继续修 | 修到一半（碰到虹膜裁切框被散点撑大的问题），在 10-30 00:01（北京时间）收到指令“立刻停止 r02 的原图抠像素路线”，改成逐件生成 |
| r03/r04 | 每个部件都让图像生成工具单独重画；10-30 00:00 还写成了硬规定：“禁止抠原图像素” | r04 交了 56 层，失败：整体横截面宽度在 y=50 处多了 9.92%，在 y=500 处多了 14.99%；右眼开口偏窄；“画风和神态仍不像原图”；中途还出现过整张脸被误生成、方形瞳孔 |
| r05 | 10-30 07:34 阿年纠正：**优先抠原图，取不到的嘴内、耳根等部位才补画** | 见坑3 |

- **原因**：每个部件单独生成，轮廓、笔触、光照、神态没办法同时对上原图；按外接框缩放摆放，框对上了，框里的眼形和比例却没对上。
- **修法**：改回“看得见的部分用原图像素，只补画被挡住的部分”。
- **教训**：r01、r02 失败是执行问题（图层混在一起、残留、断片），**不能拿来证明“抠原图走不通”**。真正证明走不通的是 r04 那条“对定稿立绘逐件重画”的路。博主那条路是先让 AI 画一张专门用来拆件的原图，起点不同，不能直接照搬。

## 坑3 修隐藏件时动了可见像素，越改越坏

- **现象**：r05 默认状态下，可见区域的 RGB 和原图差为 0。但当时把人物内部原本 252/253 的 alpha 统一改成了 255，于是和原图相比 alpha 最大差 16。另外，单独拿出每一层来看，问题很多：脸部光影层里烘进了镜框和刘海的形状，像一副“幽灵眼镜”；边缘有灰白闪点；眼白有洞；虹膜从中间断开；人耳碎成条状。r06、r07 为了修这些隐藏件，动到了看得见的像素：眼睛像在翻白眼，脖子出现裂缝，头发轮廓外飘着碎片。阿年说“丑得想吐”。
- **原因**：没有把“默认状态可见像素不许动”定成硬门槛；验收时只看拼合图，没有一层一层看。
- **修法**：r06、r07 作废，回到 r05 重新做；规定每次交付前先算默认状态和原图的逐像素差，**最大差必须是 0**。r08 做到了整张 RGBA 零差：嘴通过，眼睛没过（闭眼补丁顶到了头发上，补丁是平涂的，眼线末端像梳齿，眼白是一块硬块，虹膜上沿被横着切平）。r08-r2 把这 9 项加上牙齿边缘都修好，于 14:25 通过。
- **教训**：零差是硬门槛，而且要说清楚是拿什么和什么比。验收时要单独看每一层。

## 坑4 建模早期的三个坑

- **加载成功，画面却一片空白**：渲染器没有处理 Core 的 Y 轴和 UV 翻转（V1）。
- **测试绑定了旧模型的哈希**：结果用旧证据通过了新模型。测试必须拒绝和当前文件对不上的证据。
- **耳尖贴着画布边缘**：大角度转头时耳尖被裁掉。画布四周要留出余量。

## 坑5 动作手感的四个坑

- **V2 第一次交付，阿年说“几乎看不出区别”**：录屏只截了待机最开始的 4 秒，那几秒正好处在停留段；而且动作幅度设得太小。修法：把真实幅度调大，录像里专门安排能看出变化的片段。
- **嘴“像割开一条缝”**：整条闭嘴线都分给了上唇，下唇单独往下拉。修法：按原图上下唇的接触曲线把两片唇拆开，嘴角共用。
- **摸一只耳朵，头发也跟着动**：原来的“轻戳”给所有物理组施加的是同一阵风。修法：左右耳各用一个独立输入。
- **转头像在扯脖子**：脖子上端只少量跟随头部，下端和衣领固定不动。
- 口型到现在还不够满意：最新一版装上后，阿年说嘴“动了但粗糙”，以后单独开单处理。

## 坑6 只在说话时出现的左眉灰线

- **现象**：r1 装机前，拆帧检查发现三个问题：左眉上方的头发里有一道浅灰色横线；转头时脖子的轮廓滑到了蓝色领口上；转头时头发边缘有零星的白点和黑点。r2 修好了后两个，但**灰线在说话那一段（20.0–27.5 秒）每一帧都还在**。
- **原因**：说话时，运行端除了嘴，还会同时写入 `ParamEyeLSmile/RSmile`（0.08×）和 `ParamMouthForm`（0.4×）。画面左侧那块眉毛网格里带着原图的头发，眼睛微笑参数一变，整块就被挪开，露出下面浅色的接缝。r2 做“说话”静态检查时，漏掉了眼睛微笑这个输入。
- **修法**：r3 只解除了这一块网格和眼睛微笑之间的附带联动，然后用 94 组 Core 对比确认，只有这一块发生了变化。
- **教训**：检查要用运行端真实会同时写入的参数组合，单独推一个参数是查不出来的。

## 坑7 闭眼改了四版

| 版本 | 输入的问题 | 实际修改 | 剩下的问题 |
|---|---|---|---|
| r4 | 阿年在真机上看，说“闭眼很奇怪”：线太黑太粗，补丁比周围亮 | 闭眼线改细到约 1.12 像素，皮肤补丁加了阴影和羽化 | 线太细了，手机大小下“整张脸像没有眼睛”；补丁太大，颜色太平 |
| r4b | 上一版剩下的问题 | 线的中段 2.8 像素，两头收尖，外眼角带拖尾，沿原来的下眼缘走；补丁只盖住眼睛开口 | 线通过了；补丁里混进了头发的颜色，羽化后变成竖条纹；右眼外沿发红；半眨眼时边缘是白色锯齿 |
| r4c | 上一版剩下的问题，加上阿年想要《代号鸢》动态 CG 里那种闭眼的层次感，但脸和眼形要保持自己的 | 改成沿眼皮平滑取色（去掉竖条色带），加上随闭眼一起移动的浅褶和柔和阴影 | 阿年觉得眼周的模糊范围太大，闭眼的黑边有锯齿 |
| r4d | 上一版剩下的问题 | 补丁上下沿往回收（上沿收 1.4 个原生像素，下沿收 1.2 个）；**补丁覆盖面积减少 12.05% / 11.45%**；**半透明柔化区域减少 42.43% / 42.13%**；黑边单独做抗锯齿 | 阿年在真机上看：“这次真的好看了” |

- **教训**：施工单写的是“跟原图下眼线一样粗”，不是越细越好。数字全对，看起来不对，也不算通过。r4c 的改进来自专门回去重看了那段动态 CG 里闭眼的几秒。所以参考资料平时以整理好的文档为准，但碰到新问题时要回到原始资料去看。

## 坑8 装手机

- **V1 黑屏**：模型已经建好，但待机动作还没加载完，动画就去访问一个空对象，RAF 因此停住了。修法：所有东西都就绪后再开始绘制。
- **更新被自动回滚**：远程更新时 Shizuku 停了，第一次送包自动回滚了。送包前要确认脸页在前台、处于空闲，并且 Shizuku 在运行。r4d 第一次送包时报“keep the eyes page open and idle”，阿年重新打开页面后才通过。
- **许可证文件被白名单拒收**：Framework 的许可证一开始是按 `.md` 打包的，但 `.md` 不在更新器允许的后缀里。后来把许可证原文完整存成 `.LICENSE.json`，**没有为此扩大更新器的权限**。
- **返回缓存后页面没法继续**：H 窗口复现过这个问题：`pagehide` 时把进入返回缓存的模型释放了，用户返回时页面就接不上。修法是判断 `persisted`，进入返回缓存时只复位，不释放。
- **口型数据源**：脸页一开始只能拿到“正在说话”这个状态，拿不到真实音频。H 窗口如实标成 BLOCKED，没有用正弦波去假装嘴在动。后来电话音频从现有的输出 gain 分支接 Analyser，日常播放则在脸页里解码同一段 MP3，按 20ms 计算包络。
- **当时实际读回了什么**（应该做到的标准，是版本状态和每个运行文件的哈希都读回来）：

| 装机 | 当时实际读回 | 没做的 |
|---|---|---|
| H 首次接入（10-29） | 已安装 / 版本 / 当前版本 / 页面就绪四项一致；**通过 USB 逐个读回 16 个文件，SHA 全部一致**；前台页面确认 | 外屏观感、真实声音、30 分钟发热 |
| r3（10-30 17:5x） | 已安装 / 当前版本 / 页面就绪三项为同一版本 | **回滚基线没有在手机上实际读回**（人在工位，没带 USB），只是推断 |
| r4d（10-30 22:4x） | 已安装 / 版本 / 当前版本 / 页面就绪为同一版本 | 没有记录逐个文件的哈希读回（记录里没写清） |

- **发热**：10-30 刚打开 Live2D，手机就到了 40.6℃；30 分钟的温度和帧率对比，到现在也没有完整数据（记录里没写清）。
- **教训**：上传被接受不等于装好了；写清楚当时实际读回了什么，不要写成“应该是好的”。

## 坑9 Windows 桌宠

### 交付前在 Mac 上就复现并修好的三个问题
- **socket 超时管不住总耗时**：`timeout` 只管“多久没收到数据”，服务器一点点慢慢回数据时，总时长会超出 8 秒和 20 秒的预算。修法：主请求和兜底请求都放进有绝对截止时间的传输线程里，到点就取消。我们用本机的假服务器慢速返回数据来测试，先看到测试失败，修好后再通过。
- **取消后 HTTPConnection 会自动重连**：已经过期的请求还是会被发出去。修法：关闭自动重连（`auto_open=0`），再加一条确定性的竞态回归测试。
- **120 字的字幕看起来显示出来了，其实最后一行被裁掉了**，还和“在听…”重叠。修法：逐步缩小字号，太长就分页；用 `scrollHeight <= clientHeight` 检查。

### Windows 现场踩的十一个坑（11-04 晚，沈砚和阿年在真机上调试）

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | 安装包没下载完，只留下一个 `.zip.wxdownload` | 用微信内置浏览器下载，中途停了 | 换正经浏览器下载；在家里局域网直接从 Mac 下载，比绕出去走隧道快很多 |
| 2 | PowerShell 报溢出 | Windows PowerShell 5.1 里 `[Math]::Max(0, double)` 选中了 Int32 重载；计时起点是 `DateTime.MinValue` 时就会溢出 | 参数一律写成 `[double]` |
| 3 | 单实例锁不可靠，第二次启动时直接静默退出 | 依赖 Mutex 构造函数的 `[ref]` 输出参数 | 改用 `WaitOne(0)`；捕获 `AbandonedMutexException` 时当作已经拿到锁；已经有实例在运行时弹窗提示 |
| 4 | 桌宠启动后悄悄退出，消息也丢了 | 由 PowerShell 启动 Electron 时，主进程在 Windows 上拿不到可用的 stdin | 改用私有命名管道，通过 `--desk-pipe=<随机名>` 传给 Electron |
| 5 | 拖动时窗口越拖越大 | 屏幕缩放 125% 时，`win.setPosition` 每次都会让窗口变大一点 | 改用 `setBounds` 并固定宽高，同时设置最小和最大尺寸 |
| 6 | 发过去的“替换文件”没有生效 | 通过 Telegram 发送的文件在 Windows 上被存成了 `desk-overlay(2).ps1`；还有人把 `.ps1` 打成了 `.psl` | 改成一行更新命令，自动下载、清理 `(2)` 副本、重启，并上传诊断报告 |
| 7 | 服务器上的服务突然死掉 | 服务是从沈砚自己的 shell 里启动的，和沈砚的服务在同一个 cgroup 里，那边一重启，这边就被一起杀掉了 | 改用 crontab `* * * * *` + `flock` 保活 |
| 8 | 鼠标侧键上下反了 | 鼠标驱动软件自定义了侧键，把 XBUTTON1 和 XBUTTON2 对调了 | 在配置里对调 `side_button` 和 `voice_button` |
| 9 | 按住说话后提示“超时” | 服务端只在沈砚的会话空闲时才把语音送进去；沈砚正忙时，20 秒的窗口就过期了 | 设计上的缺口，**还没改** |
| 10 | 截图“直看”总是失败 | 识图模型把 JSON 包在 ```json 代码块里，而且描述超过了 40 字，于是每张都被丢弃 | 解析前去掉代码块标记；描述太长就截断，不再整张丢掉 |
| 11 | 没有声音 | Windows 的默认输出设备是一副没人戴的耳机 | 改回正确的输出设备 |

- **实测状态（11-04 23:16）**：在沈砚会话**空闲**时，全链路在阿年的 Windows 上通过：透明显示、字幕、声音、嘴型、眨眼，以及按住说话 → 转写 → 送进沈砚会话 → 回话。截图直看在修掉识图解析问题后也通过了。**会话忙时说话会过期丢弃**（第 9 条），这个场景没有通过。跨屏、拔副屏、30 秒截断、权限关闭、断网这几项，当晚没有逐项实测。
- **教训**：这些现场修复，原来的测试一个都没覆盖到（原测试用的是 Electron API 的 mock，Mac 上也跑不了 Windows PowerShell），以后回归测试要补上。Mac 上的 mock 通过，不等于 Windows 上能用。

## 最该记住的十条

（[README](../README.md) 里的三条之外）

1. 参考资料整理成文档，平时以文档为准；文档有矛盾、缺内容，或者遇到新问题时，回原始资料去查。
2. 默认状态零差是硬门槛，要说清楚拿什么和什么比；零差以 PNG 为准，不以 PSD 为准。
3. 每一层单独铺在灰底上看；动态效果要拆帧看。
4. 用运行端真实会出现的参数组合来检查。
5. 只有 Core 没有物理；每帧的计算顺序是固定的。
6. 下游不许替上游打补丁：哪一步出了问题，就退回哪一步。
7. 施工单要写死目标、保护对象、授权范围和验收标准；方法要附上依据和失败时怎么办，不要把没验证过的方法写成铁律。
8. 原本就失败的测试单独列出来，绝不放宽断言；没全部测过就不说“好了”。
